# 命名递归 / 整数字面量目标类型 / 嵌套无括号调用修复

日期：2026-08-27

本批修复三个已存在但实现不完整的语言行为，不引入兼容层。

## 顶层命名函数自引用

顶层 `func` 在检查自己的函数体前会先把自身完整签名登记到当前顶层作用域，因此：

```alias
func u32 down = (u32 x) -> {
    if x == 0 { return 1 }
    return down(x - 1)
}
```

可以直接按绑定名递归。

这不是一般前向引用：后面才声明的其它函数仍不可见。codegen 原本就会在发射函数体前预分配全部顶层槽位，本次不修改闭包 ABI。

## 二元表达式中的整数字面量

当左操作数已经具有明确的有符号/无符号整数类型时，右侧**整数字面量**使用该类型作为目标槽，并执行现有的字面量范围检查。例如 `u32 x` 下的 `x == 0`、`x - 1` 均按 `u32` 检查。

该规则只适用于字面量：`u32` 变量与 `i32` 变量之间仍禁止隐式混算，显式转换规则不变。

## `println f 0` / `print f 0`

语句位置允许输出内建的唯一实参本身是一个普通单参无括号调用：

```alias
println fact_while 0
```

等价于：

```alias
println(fact_while(0))
```

这不会改变 P2e 的既有二元绑定规则：`dup 5 + 1` 仍然拒绝，必须写 `(dup 5) + 1`。

## 验证

新增 `tests/recursion_literal_noparen_laws.rs`，覆盖：

- `public func u32` 命名递归；
- `x == 0` / `x - 1` 的整数目标类型；
- 字面量越界诊断；
- 不允许 `u32`/`i32` 变量隐式混算；
- 旧无括号二元规则不回退；
- 不开放后续函数前向引用。

仓库永久禁用 CI；验证继续使用显式手动 `cargo test --all-targets`。
