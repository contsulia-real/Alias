# 命名递归 / 整数字面量目标类型 / 无括号调用专题

**首次修复：** 2026-08-27  
**同步日期：** 2026-08-28  
**当前基线：** M69 typed HIR 之后仍有效

> 本文记录三类最初集中修复的问题，并同步其后续扩展后的**当前状态**。总规范以 `docs/spec-notes.md` 为准。

## 1. 顶层命名函数自引用

顶层 `func` 在检查自己的函数体前先登记自身完整签名，因此：

```alias
func u32 down = (u32 x) -> {
    if x == 0 { return 1 }
    return down(x - 1)
}
```

合法按绑定名递归。

该规则只建立函数对**自身**的可见性，不开放后续声明的普通前向引用。

此后 Alias 还加入了 `this`：每个 func 体内存在不可变的当前函数自引用，携带完整函数签名；改名不影响递归，嵌套 func 会重新绑定自己的 `this`。因此当前既支持按函数名递归，也支持 `this` 递归。

## 2. 整数字面量与目标类型

最初修复的典型问题是：当一侧已经有明确整数类型时，另一侧整数字面量必须按该类型检查，而不是无条件默认成 `i32`。

例如 `u32 x` 下：

```alias
x == 0
x - 1
```

其中 `0` / `1` 都按 `u32` 目标检查。

当前规则已经扩展为完整目标类型传播体系：

- 声明初始化；
- 普通赋值；
- 字段默认值；
- 结构体构造/字段赋值；
- return；
- 函数/方法实参；
- array 元素；
- result payload；
- match / 三元分支；
- 字符串插值；
- 数值和位运算复合表达式。

目标类型可向**字面量**、`from/try_from` 和支持递归传播的复合表达式继续传递，但不会把已有变量偷偷改型。因此 `u32` 变量与 `i32` 变量之间仍禁止隐式混算。

整数字面量当前范围：

- 无上下文正整数默认依次尝试 `i32 → i64 → u64`；
- 负整数最大为 `i64`；
- 进入已知整数目标槽时按目标类型检查，不截断；
- 整数 `+/-/*`、一元负号、左移和 `increase/decrease` 当前均为 checked 语义，越界报「整数溢出」，不再 wrapping。

## 3. `println f 0` / `print f 0`

输出内建允许其唯一实参本身是普通单参数无括号调用：

```alias
println fact 0
```

等价：

```alias
println(fact(0))
```

该特例不改变无括号调用的总体绑定规则。

仍然必须区分：

```alias
(dup 5) + 1     // 明确：先调用 dup

dup (5 + 1)     // 明确：表达式整体作为参数

dup 5 + 1       // 不解释为 (dup 5) + 1
```

零参数调用必须写 `five()`。函数值作为值传递时使用显式括号，例如 `f(g)`。

## 4. 任意函数值作为被调方

后续 M67 已进一步取消原生后端按表达式形态限制被调方的旧白名单。

当前只要表达式的静态类型是完整函数签名，就可直接调用：

- 标识符；
- `this`；
- 函数字面量；
- 三元产生的函数值；
- match 产生的函数值。

类型和调用目标已经在 `CheckedProgram` typed HIR 中固化，codegen 不得再通过表达式形态决定“能不能调”。
